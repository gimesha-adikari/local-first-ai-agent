# v0.3.0 owner acceptance guide

This guide covers the whole v0.3.0 milestone: Chat and Agent, providers,
contextual text (03-D) and screen intelligence (03-E). Engineering
verification is complete. **Every check below needs you, on a real
desktop, and none has been marked as passed.** Automated results are in
[stage 03-E](stage-03-e-screen-intelligence.md#v030-final-hardening).

Use synthetic content (test cards, sample text) wherever a step sends
something to a provider.

## 0. Before you start

1. Back up your current profile. Your profile is at schema 11 and the new
   build migrates it to schema 15 on first start:

   ```sh
   cp -a ~/.local/share/io.github.gimesha-adikari.localfirstaiagent ~/lfa-profile-backup-$(date +%F)
   ```

2. Install the acceptance package (version 0.2.0 by design; no version
   change was made). It pulls Tesseract with English data and the PipeWire
   client library. It does not install other OCR languages or any model:

   ```sh
   sudo apt install ./target/release/bundle/deb/local-first-ai-agent_0.2.0_amd64.deb
   ```

   Run it from the repository root. If an earlier 0.2.0 package is installed,
   add `--reinstall`.

3. Optional OCR languages (about 19 MB on disk in total; install only what
   you need):

   ```sh
   sudo apt install tesseract-ocr-spa tesseract-ocr-fra tesseract-ocr-deu tesseract-ocr-por tesseract-ocr-rus tesseract-ocr-ara tesseract-ocr-hin tesseract-ocr-chi-sim tesseract-ocr-jpn tesseract-ocr-kor
   ```

4. Launch **local-first-ai-agent** from the GNOME app grid (not from a
   terminal or IDE), so the desktop identity and portal registration match
   the installed desktop file.

**Expected:** the app opens with your existing conversations, models,
settings and memories. Settings → Privacy & Storage shows the same database
path.

## 1. Main Chat and Agent (regression)

1. Open an existing conversation. Send a short message with your local model.
2. Switch to Agent and run "Find files named ledger in a folder I choose".
   Approve the folder and read one file.
3. Knowledge: open the library, run a keyword search, attach a document to a
   Chat question.
4. Memory: add a memory, use it in Chat, delete it.

**Expected:** behaviour as in v0.2.0 and 03-C. Answers stream, Stop works,
receipts show "on this device".

## 2. Providers

1. Settings → Providers. Add a **self-hosted** server if you have one
   (for example llama.cpp or Ollama on localhost). Test it.
2. Add one **cloud** OpenAI-compatible provider. Enter the key in the
   native dialog (it is stored in the keyring). Set retention, sharing and a
   small monthly limit. Enable **image input** only if the provider's model
   accepts images.
3. Turn Local-only off, select the provider for Chat, and send a small
   synthetic request, for example "Reply with the word ORCHARD".

**Expected:** the review lists exactly what is shared; the receipt shows the
provider origin, transmission "sent" and usage. Provider usage appears in
the provider's own dashboard.

## 3. Global shortcut and contextual clipboard intelligence

1. Settings → General → Configure desktop shortcut. Bind a key in the
   GNOME dialog.
2. In another application, copy a synthetic paragraph and press the
   shortcut.
3. Glance opens. Choose Read clipboard, then Explain with the local model.
4. Choose your provider, review, and send.
5. Dismiss with Escape and check that focus returns to the other app.

**Expected:** the panel is ready almost instantly after the first summon;
nothing is read until you choose Read clipboard; the review shows the
clipboard text and the provider; the receipt lists the clipboard source.

## 4. Screen capture consent and region selection

1. In Glance choose **Capture region**.
2. **Expected:** the panel hides; GNOME's consent dialog names the app.
   Choose Cancel. **Expected:** "Screen sharing was not allowed. Nothing was
   captured."
3. Capture again. **Expected:** the dialog asks again (no remembered
   permission). Choose Share.
4. **Expected:** the sharing indicator appears briefly and disappears before
   the frozen overlay is shown.
5. On the overlay: drag a region, move it, resize with the handles, nudge
   with arrow keys, confirm with Enter or Use region. Repeat once and cancel
   with Escape or Cancel.
6. Note whether the overlay accepts keys without a click first (focus policy
   is compositor-dependent).
7. If available: repeat on a HiDPI or fractional-scaling display and on each
   monitor of a multi-monitor setup.

**Expected:** the preview in Glance matches the region exactly; the notice
says the stream closed; nothing was processed yet.

## 5. OCR and translation

1. Capture a region of real application text in English. Choose
   **Extract text**.
2. Open Languages, choose another installed language, capture text in that
   language, extract it.
3. Choose Translate, target "English", process with the local model.
4. Try right-to-left text (for example Arabic or Hebrew) if you installed it.

**Expected:** the notice says recognition ran on this device; text is
editable and right-to-left text displays correctly; accuracy is judged by
you (the recorded thresholds are synthetic, not guarantees). If a language is
missing, the panel shows the apt command to install it.

## 6. One real visual-intelligence request

1. With the image-capable provider selected, capture a synthetic test card
   (for example a dialog with known text).
2. Tick **Send this image to …**, choose Explain, and review.
3. **Expected:** the review shows the exact region that will be sent, the
   data classes and retention, and an estimate including image tokens.
   Send.
4. **Expected:** the answer describes the region; the receipt says the
   selected region was attached; the provider's usage shows one request.
5. With a text-only provider selected, confirm the image option is absent.

## 7. Local-only activation during remote processing

1. Start a remote request that streams for a while (for example "Write 300
   words about orchards" on the clipboard or OCR text).
2. While it streams, open the main window → Settings → Providers and turn
   on **Local-only mode**.

**Expected:** the request stops within a moment; the result shows an error
and a receipt whose transmission is still "sent" (the text had already been
sent). Reopen Glance: the provider list is gone and the panel says
Local-only is on. Capture and Extract text still work, and a local Explain
still works.

## 8. Cleanup and privacy verification

1. Dismiss Glance during a capture (while the consent dialog is open),
   during OCR and during a remote request. Reopen it.
2. **Expected:** nothing remains in the panel; no indicator is left on.
3. Check for leftovers:

   ```sh
   find ~/.local/share/io.github.gimesha-adikari.localfirstaiagent ~/.cache /tmp -newer ~/lfa-profile-backup-$(date +%F) -name '*.png' 2>/dev/null
   gdbus call --session --dest org.freedesktop.impl.portal.PermissionStore --object-path /org/freedesktop/impl/portal/PermissionStore --method org.freedesktop.impl.portal.PermissionStore.Lookup screencast io.github.gimesha-adikari.localfirstaiagent
   ```

   **Expected:** no PNG files from the app; no stored screencast
   permission for the app (the Lookup call reports that it was not found).

4. Optional: KDE Plasma or an X11 session, only if support is to be claimed.

## Reporting failures

For each failure, note the step number, what you expected and what happened,
the exact message shown, and the desktop (GNOME version, Wayland or X11,
scaling, monitors). Screenshots are helpful; do not include real personal
content. Errors from capture say "Nothing was captured" when nothing left
the screen; please quote them exactly.
