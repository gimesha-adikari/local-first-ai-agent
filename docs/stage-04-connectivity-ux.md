# Stage 04 connectivity and search decision

The product owner removed the global Local-only operating mode on November 28, 2026. This supersedes the earlier operating-mode requirement. Local, cloud and self-hosted generation remain explicit Chat targets. The app opens a connection for a requested operation, such as sending to the selected provider, searching, reading an entered public webpage or downloading a curated model. Starting the app, opening a catalog and migrating a profile do not initiate those operations.

The deterministic Rust boundary still admits each request against its destination, request body and route, data classes, purpose, credentials, limits and live authorization. Stop and operation-level revocation terminate the applicable work. Provider sharing preferences still govern eligible conversation history, memories and documents. Attachments and contextual captures retain their review and sharing controls. Visual-derived search requires review of the exact outgoing text. The search service receives the query, public-page retrieval stays bounded, and sending a question and web excerpts to a model provider remains a separate choice. Purili requires recorded acceptance of its personal, non-commercial terms.

Schema 20 preserves the effective Chat target. A profile previously using Local-only opens with the local Chat target. Its remote provider settings and credentials are available for explicit reselection. A profile previously using an active remote target keeps that selection. The migration removes the obsolete column in the database transaction. A build limited to schema 19 requires a pre-upgrade backup.
